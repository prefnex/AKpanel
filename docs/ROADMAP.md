## 1. الرؤية والهدف من المشروع

لوحات التحكم التقليدية (مثل cPanel و CWP) تعاني من:
- استهلاك مرتفع للموارد والذاكرة (RAM).
- واجهات مستخدم قديمة ومشتتة.
- تعقيد في الإعداد والارتباط بنظام تشغيل قديم.
- صعوبة إدارة التطبيقات الحديثة (Node.js, Single Page Apps, APIs).

**هدف AKpanel:**
تقديم بديل عربي/عالمي حديث مستوحى من أحدث التجارب العالمية (مثل CloudPanel و Coolify)، يتميز بـ:
- **سرعة وخفة استثنائية:** استخدام **Goravel (Go)** كـ Single Binary مستقل مع **SQLite** كمحرك داخلي، باستهلاك رام أقل من 20MB وبدون اشتراط تثبيت Node أو PHP لتشغيل اللوحة نفسها.
- **عصرنة التصميم:** واجهة Dark Mode مريحة للعين تعتمد على Glassmorphism وبطاقات معلومات تفاعلية.
- **أمان وسيطرة كاملة:** عزل كامل لمواقع العملاء، مع إدارة دقيقة لملفات Nginx وخدمات Systemd.

## 2. الهندسة المعمارية للنظام (System Architecture)

يعتمد النظام على 3 طبقات رئيسية متناسقة:

```
┌─────────────────────────────────────────────────────────────┐
│             الواجهة الأمامية (Frontend Dashboard)          │
│       Vue 3 + Vite + Modern Glassmorphism Theme + xterm.js   │
└──────────────────────────────┬──────────────────────────────┘
                               │  REST API + WebSockets
┌──────────────────────────────▼──────────────────────────────┐
│           الباك إند والنظام الأساسي (AdonisJS v6)            │
│  - System Services Runner   - Nginx Vhost Generator         │
│  - Multi-PHP Pool Manager   - SQLite Internal Database      │
│  - Real-time PTY Terminal   - Auth & Role Permissions       │
└──────────────────────────────┬──────────────────────────────┘
                               │  System Commands / Sockets
┌──────────────────────────────▼──────────────────────────────┐
│             نظام التشغيل (Ubuntu 22.04 LTS VPS)             │
│  - Nginx (Web Server)       - PHP-FPM (7.4 -> 8.4)          │
│  - MariaDB / MySQL          - UFW & Fail2ban                │
│  - Linux Users / Quotas     - Systemd Services              │
└─────────────────────────────────────────────────────────────┘
```

## 3. بيئة التطوير المعزولة (Dockerized VPS Environment)

لكي نضمن إمكانية التطوير السلس دون المساس ببرامج جهازك المحلي (مثل FlyEnv):
- نقوم بإنشاء حاوية Docker تحتوي على **Ubuntu 22.04 LTS** مع تثبيت كامل لـ Nginx و Node.js و PHP-FPM.
- **المنافذ المعزولة:**
  - `3333`: لوحة التحكم (AKpanel Dashboard).
  - `8080`: استعراض المواقع التجريبية التي تنشئها اللوحة بدلاً من المنفذ 80.
  - `8443`: استعراض المواقع عبر HTTPS بدلاً من المنفذ 443.
- **الربط المباشر (Volume Mount):** مجلد المشروع مربوط بالحاوية لتطبيق أي تعديل في الكود لحظياً (Hot-Reload).

## 4. تفاصيل كل ميزة واستخداماتها وكيفية بنائها برمجياً

---

### 4.1 لوحة الإحصائيات والمراقبة الحية (Dashboard & Real-Time Metrics)
* **الوصف والاستعمال:**
  - عرض حالة السيرفر بلمحة واحدة: نسبة استخدام المعالج (CPU)، استهلاك الذاكرة (RAM)، المساحة المتبقية على القرص الصلب (Disk)، سرعة نقل البيانات (Network I/O)، ومعدل التحميل (Load Average).
  - بطاقات حالة الخدمات الأساسية (Nginx, PHP-FPM, MySQL, UFW) مع إمكانية إعادة التشغيل (Restart) بنقرة زر.
* **كيف سنبنيها برمجياً؟**
  - إنشاء `SystemService` في AdonisJS يقرأ بيانات النظام من `/proc/stat` و `/proc/meminfo` وأمر `df -h` وحالة الخدمات عبر `systemctl is-active <service>`.
  - إرسال البيانات دورياً كل ثانيتين عبر **WebSockets / Server-Sent Events (SSE)** للواجهة لتحديث العدادات والمخططات البيانية المتحركة بسلاسة تامة.

---

### 4.2 إدارة المواقع والنطاقات (Websites & Virtual Hosts)
* **الوصف والاستعمال:**
  - إضافة موقع جديد (WordPress, Laravel, Node.js, Static HTML, Reverse Proxy).
  - تحديد المسار الجذري (`Document Root`) مثل `/var/www/sites/example.com/public`.
  - اختيار إصدار PHP الخاص بهذا الموقع تحديداً.
  - إدارة النطاقات الفرعية (Subdomains) وإعادة التوجيه (301/302 Redirects).
  - صفحة خاصة لتعديل ملف إعدادات Nginx المباشر مع التحقق من الأخطاء قبل الحفظ.
* **كيف سنبنيها برمجياً؟**
  - إنشاء نظام قوالب ذكي (Nginx Templates) مخصص لكل نوع موقع (PHP FastCGI، Proxy Pass، Static).
  - توليد ملف الإعداد وحفظه في `/etc/nginx/sites-available/{domain}.conf` وعمل رابط رمزي في `sites-enabled`.
  - فحص صحة الملف برمجياً باستخدام `nginx -t`؛ وإذا كان صالحاً يتم تنفيذ `nginx -s reload`، وفي حال وجود خطأ يتم رفض التعديل وتنبيه المستخدم فوراً بالسطر المسبب للخطأ.

---

### 4.3 محرك تشغيل وإدارة إصدارات PHP المتعددة (Multi-PHP Engine)
* **الوصف والاستعمال:**
  - دعم تشغيل عدة إصدارات في نفس الوقت: **PHP 7.4, 8.0, 8.1, 8.2, 8.3, 8.4**.
  - تخصيص `PHP-FPM Pool` معزول لكل موقع بصلاحيات مستخدم Linux خاص لزيادة الأمان ومنع اختراق المواقع لبعضها.
  - تعديل المتغيرات الشهيرة في `php.ini` من الواجهة (مثل: `upload_max_filesize`, `memory_limit`, `max_execution_time`, `opcache`).
  - إدارة وتفعيل الإضافات (PHP Extensions مثل `curl, gd, mbstring, zip, pdo_mysql, redis`).
* **كيف سنبنيها برمجياً؟**
  - الاعتماد على مستودع `ondrej/php` الرسمي لنظام Ubuntu.
  - كتابة ملفات Pool مخصصة في `/etc/php/{version}/fpm/pool.d/{domain}.conf` تستمع على Unix Socket خاص بالموقع.
  - واجهة تحكم تقرأ وتعدل قيم `php.ini` مع إعادة تشغيل الـ FPM الخاص بالإصدار المطلوب فقط دون التأثير على بقية المواقع.

---

### 4.4 إدارة قواعد البيانات (Database Manager)
* **الوصف والاستعمال:**
  - إنشاء قواعد بيانات MySQL / MariaDB / PostgreSQL.
  - إنشاء مستخدمين لقواعد البيانات وتعيين الصلاحيات وتوليد كلمات مرور قوية.
  - الدخول بنقرة واحدة (One-Click Login) إلى مدير قواعد البيانات الخفيف (**Adminer** أو **phpMyAdmin**).
  - استيراد وتصدير قواعد البيانات (SQL Dump / Import / Export).
* **كيف سنبنيها برمجياً؟**
  - بناء `DatabaseService` يتصل بـ MySQL عبر Socket بصلاحيات إدارية وينفذ استعلامات إنشاء القواعد والمستخدمين (`CREATE DATABASE`, `GRANT ALL ON...`).
  - تجهيز مسار مخصص وآمن لـ Adminer مدمج باللوحة مع تسجيل دخول تلقائي مشفر.

---

### 4.5 شهادات الأمان والحماية (SSL & Security)
* **الوصف والاستعمال:**
  - إصدار شهادات Let's Encrypt مجانية بنقرة زر واحدة لكل نطاق ونطاقاته الفرعية.
  - التجديد التلقائي لشهادات SSL قبل انتهائها (Auto-Renew).
  - إمكانية تركيب شهادة SSL مخصصة (Custom SSL / Cloudflare Origin Certs) برفع الـ Certificate والـ Private Key.
  - خيار تفعيل التحويل التلقائي لـ HTTPS (Force HTTPS) وتفعيل HSTS.
* **كيف سنبنيها برمجياً؟**
  - دمج أداة `acme.sh` أو `certbot` واستدعائها عبر الباك إند لإجراء التحقق من ملكية النطاق (HTTP-01 Challenge).
  - دمج ملفات الشهادات الناتجة تلقائياً في قالب Nginx Vhost وإعادة تحميل الخدمة.
  - جدولة مهمة Cron يومية لفحص الشهادات القريبة من الانتهاء وتجديدها تلقائياً.

---

### 4.6 جدار الحماية والأمان (Firewall & Fail2ban)
* **الوصف والاستعمال:**
  - واجهة رسومية سهلة لإدارة جدار الحماية **UFW** (فتح بورت، إغلاق بورت، حظر آي بي IP معين).
  - مراقبة محاولات الاختراق وهجمات التخمين (Brute-Force) وحظر المهاجمين تلقائياً عبر **Fail2ban**.
  - تغيير منفذ الـ SSH الافتراضي وتعيين مفاتيح SSH Keys من الواجهة.
* **كيف سنبنيها برمجياً؟**
  - قراءة وكتابة قواعد UFW عبر أوامر النظام (`ufw status numbered`, `ufw allow/deny <port>`).
  - قراءة قائمة الآيبيهات المحظورة في سجون Fail2ban (`fail2ban-client status sshd`) مع إمكانية فك الحظر (Unban) بنقرة زر.

---

### 4.7 مدير الملفات ومحرر الأكواد (Modern File Manager & Monaco Editor)
* **الوصف والاستعمال:**
  - تصفح ملفات المواقع بواجهة تشبه مستكشف الملفات الحديث (Tree View & Grid View).
  - رفع الملفات (Drag & Drop)، التحميل، الحذف، إعادة التسمية، ضغط وفك ضغط الأرشيف (`.zip`, `.tar.gz`).
  - تعديل صلاحيات الملفات والمجلدات (`chmod 755/644` و `chown`).
  - **محرر أكواد احترافي مدمج (Monaco Editor - المحرك المستخدم في VS Code)** يدعم التلوين البرمجي لملفات `.php`, `.js`, `.env`, `.json`, `.conf`, `.html`.
* **كيف سنبنيها برمجياً؟**
  - بناء `FileService` في AdonisJS مع قيود أمان صارمة تمنع ثغرات مسارات الملفات (Path Traversal / Jail to site root).
  - استخدام مكتبة `Monaco Editor` في الواجهة الأمامية مع دعم الحفظ الفوري واختصارات لوحة المفاتيح.

---

### 4.8 محطة الأوامر الحية وسجلات النظام (Web Terminal & Live Logs)
* **الوصف والاستعمال:**
  - فتح شاشة Terminal سوداء كاملة التفاعل داخل المتصفح لإدارة السيرفر مباشرة دون الحاجة لبرامج خارجية مثل PuTTY.
  - عارض سجلات حي (Live Log Streamer) لمشاهدة سجلات أخطاء المواقع و Nginx (`access.log` و `error.log`) لحظة بلحظة أثناء زيارة الموقع.
* **كيف سنبنيها برمجياً؟**
  - ربط مكتبة `node-pty` في الباك إند لإنشاء جلسة Pseudo-Terminal حقيقية وتوصيلها بالواجهة عبر WebSocket باستخدام `xterm.js`.
  - قراءة السجلات عبر `tail -f` وبث الأسطر الجديدة فور حدوثها.

---

### 4.9 دعم التطبيقات الحديثة (Node.js & Python & Docker)
* **الوصف والاستعمال:**
  - تشغيل تطبيقات **Node.js** (Next.js, Express, Adonis) وإدارتها عبر **PM2**.
  - تشغيل تطبيقات **Python** (Django, FastAPI, Flask) عبر Gunicorn/Uvicorn.
  - إمكانية تشغيل وإدارة حاويات **Docker** للمشاريع الجاهزة.
* **كيف سنبنيها برمجياً؟**
  - إنشاء بروفايل في Nginx كـ `Reverse Proxy` يوجّه الترافيك للمنفذ الداخلي الخاص بالتطبيق (مثل `127.0.0.1:3000`).
  - التحكم في عمليات PM2 عبر الـ CLI الداخلي لـ AdonisJS.

---

### 4.10 المهام المجدولة (Cron Jobs Manager)
* **الوصف والاستعمال:**
  - إضافة وتعديل مهام الكرون (Cron Jobs) الخاصة بالمواقع والسيرفر (مثل تشغيل `php artisan schedule:run`).
  - قوالب زمنية جاهزة للمستخدم (كل دقيقة، كل ساعة، يومياً في منتصف الليل، أسبوعياً، أو مخصص).
  - حفظ سجل لمخرجات تنفيذ المهام (Output Logs) لمعرفة ما إذا كانت المهمة نجحت أم فشلت.
* **كيف سنبنيها برمجياً؟**
  - قراءة وتعديل ملفات Crontab للمستخدمين (`/var/spool/cron/crontabs/<user>`).

---

### 4.11 النسخ الاحتياطي والاستعادة (Backup & Disaster Recovery)
* **الوصف والاستعمال:**
  - إنشاء نسخة احتياطية كاملة لموقع معين (الملفات + قاعدة البيانات) بضغطة زر.
  - جدولة النسخ الاحتياطي التلقائي (يومي / أسبوعي).
  - دعم تصدير النسخ ورفعها تلقائياً إلى وحدات تخزين سحابية (Amazon S3, Google Drive, Backblaze B2, SFTP).
  - استعادة النسخة الاحتياطية بنقرة واحدة (One-Click Restore).
* **كيف سنبنيها برمجياً؟**
  - استخدام أدوات أرشفة سريعة وضغط (`tar -czf` و `mysqldump`).
  - استخدام حزم التخزين السحابي لرفع الملفات وجدولتها في Background Queue.

## 5. المراحل التنفيذية وجدول الإنجاز (Implementation Phases)

| المرحلة | المهام الرئيسية | النتيجة الملموسة |
| :--- | :--- | :--- |
| **المرحلة 1: بيئة العمل والنواة الأساسية** | تجهيز Dockerfile (Ubuntu 22.04) + تثبيت AdonisJS v6 + إعداد قاعدة بيانات SQLite + الواجهة الأمامية Vue 3 الأساسية. | الحاوية تعمل، وتفتح لوحة التحكم على المنفذ `3333` بنجاح. |
| **المرحلة 2: لوحة الإحصائيات والمراقبة الحية** | بناء `SystemService` وقراءة الموارد وبثها عبر WebSockets + تصميم واجهة الـ Dashboard والعدادات الحية. | شاشة متطورة تعرض المعالج والرام والقرص وحالة الخدمات وتتحدث كل ثانيتين. |
| **المرحلة 3: إدارة المواقع ومحرك Nginx** | بناء `NginxService` لإنشاء الـ Virtual Hosts + قوالب المواقع + تشغيل Nginx واختبار المواقع على المنفذ `8080`. | القدرة على إنشاء موقع جديد وفتحه في المتصفح فوراً. |
| **المرحلة 4: محرك PHP المتعدد وقواعد البيانات** | ضبط إعدادات PHP-FPM Pools + إنشاء قواعد بيانات ومستخدمين في MySQL/MariaDB. | موقع PHP يعمل بإصدار مخصص مع اتصال بقاعدة البيانات. |
| **المرحلة 5: مدير الملفات ومحرر Monaco** | بناء `FileService` الآمن + واجهة مستكشف الملفات + محرر الأكواد المدمج. | تصفح وتعديل ورفع ملفات المواقع من داخل المتصفح مباشرة. |
| **المرحلة 6: محطة الأوامر وسجلات النظام** | دمج `node-pty` و `xterm.js` للـ Web Terminal + شاشة متابعة السجلات الحية. | تنفيذ أوامر Linux من داخل الواجهة ومراقبة الأخطاء لحظياً. |
| **المرحلة 7: الأمان وشهادات SSL والنسخ الاحتياطي** | دمج Acme.sh للـ SSL + إدارة جدار الحماية UFW + نظام النسخ الاحتياطي. | لوحة تحكم متكاملة وجاهزة للإنتاج. |
